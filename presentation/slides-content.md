## Слайд 11

Транзакционные сценарии

Выдача
Проверка → остаток −1 → Loan. Одна транзакция.

Возврат
RETURNED + остаток +1. Повторный вызов безопасен.

Seed / Clear
Seed повторяем. Clear all удаляет зависимости и считает строки.

Атомарность защищает инвентарь и связи между сущностями

## Слайд 12

Пользовательские потоки

Readers
Поиск → создание → Delete

Publications
Поиск → Book / Periodical → Delete

Loans
Выбор по имени/названию → Issue / Return

Architecture
Иерархии + M:N + 7 паттернов → Seed / Clear all

Пользователь выбирает имена и названия; технические идентификаторы генерируются внутри приложения.
